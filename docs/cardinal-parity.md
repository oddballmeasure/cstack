# Cardinal parity

The plan (section 7.1) says cstack is done only when each Cardinal capability has a cstack owner and a test. This table maps each one. Paths are from the plugin root. Test names are quoted from their files. Scenarios are in `tests/scenarios/` and their results in `docs/scenario-log.md`.

Status:

- **Live**: a real headless run passed (an L3 scenario or the L4 f1 fixture, see `docs/scenario-log.md`).
- **Tested**: unit tests at 100% line and branch coverage (`npm run coverage:gates`), or a hook test. No live run yet.
- **Partial**: what is missing is named in the row.
